Extensions for ZimaOS's built-in VM manager (ZVM): autostart, snapshots, USB & PCIe passthrough, and remote storage.

–VMs –running –autostart

Starts VMs on host boot, orchestrated by VM Extras. Order: lower number starts first (0–999). Delay: seconds to wait after this VM before starting the next.
Watchdog: keeps a VM running — restarts it within ~30 s if it stops or crashes (turn the watchdog off to stop such a VM). VM Extras runs the ordered startup itself a few seconds after boot; the libvirt-native autostart flag is kept off so order & delay are honoured.

Create, revert or delete snapshots per VM. Running VMs get a full external snapshot (disk + memory) so it can be reverted; shut-off VMs get a quick internal snapshot.
Tip: prefer an ext4/xfs/btrfs storage target — exFAT/FAT cannot store sparse files, so overlay snapshots there grow to their full size.

Pass a PCI device of the ZimaOS device itself (not your PC) through to a VM via VFIO. Persistent pins it — VM Extras re-applies it if the ZVM UI strips it on re-save, and keeps it across host reboots.
Important: all devices in the same IOMMU group must go to the same VM. Never pass a device the host itself needs (boot GPU, system disk controller). Bridges cannot be passed.

ZVM exposes each VM's VNC console on the LAN without a password — anyone on the network can open a viewer and take over the VM's keyboard, mouse and screen. Set a password to close that gap.
Note: the VNC protocol only uses the first 8 characters. The password edits the VM config and takes effect on the next VM start; ZVM's own browser console will then prompt for it. VM Extras re-applies the password if the ZVM UI strips it on a re-save, and keeps it across host reboots.

Windows 11 refuses to install without a TPM 2.0. ZVM adds one by itself for guests it recognises as Windows 11 — but there is no control for it anywhere in its UI, so it can be neither forced nor turned off, and it does not reach other guests: VMs created as Linux come out with no TPM at all. Add one here for any VM.
Note: the device edits the VM config and takes effect on the next VM start. VM Extras re-adds it if the ZVM UI strips it on a re-save. Secure Boot is shown but not switched: the firmware and its NVRAM file are a matched pair, and repointing an existing VM at a different loader can leave it unable to boot — that is a rebuild, not a toggle.
